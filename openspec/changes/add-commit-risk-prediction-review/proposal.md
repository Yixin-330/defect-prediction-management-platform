# 提交风险预测与审查记录功能

## Why

课程团队当前缺少对单次代码提交的风险判断手段，代码审查依赖人工经验和主观排序，高风险的变更容易被漏掉。团队已完成产品需求、产品主线、分工和技术架构设计，但首个可用版本的功能范围和验收标准尚未具体化（见阶段汇报"当前问题"第 1、3 项）。本变更把产品主线中"分析提交 → 发现高风险变更 → 解释风险来源 → 安排代码审查 → 记录处理结果"这条链路固化为可在课程项目中跑通的首个可用版本，并作为后续模型扩展和试用验证的基线。

## What Changes

- 新增数据与特征工程流程：解析 Git 仓库提交、用 SZZ 标注历史缺陷、按 Kamei 14 维特征构建设计提交特征、清洗并持久化训练集。SZZ 标签只用于历史训练与评估。
- 新增离线模型训练与评估流程：在开源项目历史数据上训练并对比至少 8 个经典机器学习与深度学习模型，覆盖 Effort-unaware 与 Effort-aware 两类评估指标，完成数据划分、模型选型和 SHAP 等特征贡献解释，产出可复现的模型文件与评估报告。
- 新增在线预测服务：接收一次提交，复用离线阶段的特征提取规则，调用已训练模型返回风险评分、特征贡献解释和优先级排序。预测只使用提交当时可获得的信息，不等待未来修复结果。
- 新增审查记录流程：把高风险提交转成待审查项，记录审查处理结果与状态流转，形成可追溯的审查历史。
- 新增前端风险与审查界面：项目选择、风险列表、提交详情与风险解释、审查记录、项目质量趋势看板。
- 明确本变更的**非目标**：不做课程项目规模下的模型效果承诺，不接入真实课程团队试用（属于后续阶段），不实现完整的 8 模型矩阵作为交付门槛（基线先行）。

## Capabilities

### New Capabilities

- `data-feature-pipeline`: 从 Git 仓库解析提交、SZZ 历史缺陷标注、Kamei 14 维特征提取、数据清洗与持久化、训练集构建；离线训练与在线预测共用同一套特征提取规则。
- `defect-risk-model`: 模型训练、数据划分、多模型评估与选型、模型持久化，以及风险评分与特征贡献解释（SHAP）输出。
- `commit-risk-prediction`: 在线预测服务能力——给定提交返回风险评分、特征贡献解释与优先级排序，并提供项目/提交/特征的读取接口。
- `review-record`: 高风险提交转待审查项的创建、审查处理结果记录、状态流转与审查历史查询。
- `risk-review-console`: 前端项目选择、风险列表、提交详情与解释展示、审查记录操作、项目质量趋势看板。

### Modified Capabilities

无。项目当前 `openspec/specs/` 为空，本变更为全新能力。

## Impact

- **新增代码目录**：`backen/`（数据、模型、服务）、`fronted/`（前端界面），当前两者均为空目录。
- **数据资产**：需引入开源项目历史提交数据集作为训练与评估来源；课程项目仓库作为在线预测输入。
- **模型产物**：特征提取规则定义、训练好的模型文件、评估报告，需在离线与在线之间对齐（特征顺序、模型文件格式、输入输出结构）。
- **跨模块契约**：模块间的数据格式、特征顺序、模型文件与接口结构需要统一约定，并用公共样例数据提前联调（阶段汇报"当前问题"第 3 项）。
- **未确认事项**：技术栈按团队最终选型确定，本变更中出现的 Web 框架、前端框架、图表库为待确认默认值，需在实现前由团队确认；模型效果、进度百分比和具体日期不在本变更承诺范围内。
- **不影响**：现有产品文档与阶段汇报材料本身。
